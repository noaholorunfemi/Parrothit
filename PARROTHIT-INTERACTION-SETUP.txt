PARROTHIT PARROTS INTERACTION — SOCIAL FEATURES SETUP

INCLUDED
- Main Interaction page, member profiles, friend controls, avatar/profile support, room navigation and social feed integration.
- Fifteen independently themed room pages with room-specific compose text areas.
- Room join/leave, membership count, member invites, accept/decline, and an activity log.
- Participation-day-based levels and Supabase shared posts, comments/replies and reactions.

SUPABASE SETUP — RUN IN THIS ORDER
1. If `public.is_parrothit_owner()` is missing, apply `supabase/schema.sql` first and confirm the existing Admin 1 owner profile. Do not overwrite or recreate your existing member/admin accounts.
2. Run `supabase/community-interaction.sql` if it has not already been run.
3. Run `supabase/community-social-marketplace.sql` for social profiles, room/friend foundations, private profile fields and PARROT MINI MART.
4. Run `supabase/community-social-features.sql` for room invitations/activity, shared posts, comments/replies, reactions, active-day levels and profile counters.
5. Run `supabase/private-chat.sql` for private messages.
6. Run `supabase/community-admin-controls.sql` LAST for owner-only global controls and member suspension.

Keep the existing storage bucket named exactly `parrot media`, public as requested. Public-bucket media URLs are accessible to anyone who has the URL. Never put a service-role key in front-end files.

LEVEL RULES
- Novice 🐣: 0–2 active days
- Beginning 🌱: 3–6 active days
- Amateur 🎯: 7–13 active days
- Legend 🏆: 14–29 active days
- Professional 💼: 30–59 active days
- Veteran 🛡️: 60–99 active days
- Master 🧠: 100–179 active days
- Ultimate Master 👑: 180+ active days
One authenticated interaction/room/post/comment/reaction/listing action earns at most one participation-day credit per date. Repeated refreshes on the same day do not inflate the count.

LIMITATIONS TO KNOW
- The package is not automatically applied to your live Supabase project or Cloudflare deployment. Live cross-device behavior requires migrations and real two-account testing.
- Private one-to-one messages require the new supabase/private-chat.sql migration to be run in Supabase. The migration restricts message reading to sender/recipient and sending to accepted friends. Verify friend-table column names against your deployed schema before production use.
- Moderation preferences and some report controls remain browser-side preview settings, not a complete server-side moderation workflow.
- Old browser-only posts without an authenticated author cannot automatically be assigned a member identity.

SHARED POST MEDIA
- Signed-in community members upload images and voice recordings to the existing public `parrot media` Supabase Storage bucket. Install the own-folder media Storage policies included at the end of `supabase/community-social-features.sql`.
- The bucket currently has a 50 MB object limit. Uploads above that size will fail until the bucket/project limit is increased in Supabase Storage settings. Never treat an IndexedDB `idb:` media reference as a cross-device URL; it is local-browser preview data only.

Important limitations/setup:
