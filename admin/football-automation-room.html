Provider rules

  • There is no fixed number of API configurations or active providers in this manager.
  • Every active provider contributes data to the combined public LiveScore feed; activation does not replace existing active services.
  • Provider request quotas and competition coverage are still controlled by each API provider.
  • Primary selection and fallback priority are separate from your general Newsroom Automation settings.
  • Provider activation requires four working match feeds and at least one real, normalized match record.
  • OpenLigaDB uses competition/season routes and is not a worldwide date-based feed.
  • API plan limits and competition coverage are controlled by the data provider.

Data integrity

  • Public scores must come from a successful provider response.
  • Unavailable or stale provider data must be labelled, not presented as current live scores.
  • Provider responses are cached server-side for the configured interval to reduce unnecessary API requests.
  • All activated providers are queried together; provider priority helps decide which source version is preferred when two feeds report the same fixture.
  • Duplicate fixtures from different providers are merged, and provider-specific failures do not hide data returned by healthy providers.
