PARROTHIT NEWS — SUPABASE SETUP AND ADMIN SECURITY
================================================

IMPORTANT
The HTML, CSS and JavaScript are included in this ZIP. Shared publishing, shared image uploads and real administrator management work only after you connect your own Supabase project and deploy the provided Edge Functions. Do not remove the login guard or put a service-role/secret key into any website file.


CURRENT CONFIGURATION CHECK (Blog 17)
------------------------------------
- supabase-config.js contains a non-placeholder PARROTHIT project URL and a browser-safe publishable key. The key is designed to be public; never put a service-role/secret key in this file.
- This archive cannot confirm live DNS/network access or authenticate against your project from the packaging environment. Before launch, sign in to admin/login.html and verify the project accepts the key.
- To finish the live setup, run the included supabase/schema.sql in the SQL Editor, deploy the three included admin Edge Functions, and test owner-only admin actions, public display-setting reads and Storage uploads.
- Do not assume Supabase is fully live until those steps succeed; local preview mode is only a local simulation.

A. CONNECT THE WEBSITE
1. Open your Supabase project.
2. In Project Settings > API, copy the Project URL and public anon/publishable key.
3. Put those two public values in supabase-config.js. Do not put the service_role key there.
4. In Supabase SQL Editor, run supabase/schema.sql. The script is designed to be rerun and includes the categories image_url field, public display-setting read access, the parrothit-media Storage bucket/policies, and the 11-account admin cap and suspended-account field.
5. In Authentication settings, set the Site URL to your deployed website and add the correct admin/reset-password.html path to allowed redirect URLs. Configure email delivery so invitations and password reset messages can arrive.

B. SET ADMIN 1 (OWNER)
1. Create or use your own sign-in user in Supabase Authentication > Users.
2. Copy that user's UUID and run this SQL after replacing the UUID, username and display name with your actual values:

   INSERT INTO public.admin_profiles (user_id, username, display_name, role)
   VALUES ('PUT-YOUR-AUTH-USER-UUID-HERE', 'parrothitowner', 'PARROTHIT Owner', 'owner')
   ON CONFLICT (user_id) DO UPDATE SET role='owner';

3. Sign in through admin/login.html. An account without an admin_profiles row with role='owner' or role='admin' cannot access the dashboard.
4. Admin 1 (Owner) can add up to ten additional administrators in Control Room > Administrator access. Eleven administrator accounts total, including the owner, is the maximum. Only the owner can add, suspend/reactivate, or delete other admins; the owner cannot suspend or delete their own account through these controls. New account creation requires a valid email and password; a generated username can be used to sign in.

C. DEPLOY OWNER-ONLY ADMIN FUNCTIONS
From the project root, use the Supabase CLI with your project linked and run:
   supabase functions deploy parrothit-admin-create
   supabase functions deploy parrothit-admin-delete
   supabase functions deploy parrothit-admin-suspend

The functions use Supabase's server-side environment secrets. Never copy SUPABASE_SERVICE_ROLE_KEY into index.html, dashboard.html, any JavaScript file or a public repository. Make sure Supabase Auth email invitations are configured. The admin create function creates the account with the password entered by the owner and verifies the password confirmation server-side. Use an email address as the login identifier, or enter a username plus a valid recovery email; usernames can be used to sign in. Keep the service-role key only in Supabase Edge Function secrets. Run the updated schema before deploying these functions.

D. LOCAL IMAGE UPLOADS
- Article images, category images, slider images, advertisement images and media-library images each have a local file picker. A web image URL is optional when you choose a file.
- The site uploads the chosen image file to the public parrothit-media Storage bucket and saves its generated web URL with the related story/setting. Do not paste an image's base64 data into a text field.
- If an image upload fails, the dashboard displays an error instead of pretending the file is publicly hosted. Run the schema file, ensure the current admin profile exists, and verify the Storage policies before uploading again.
- Older base64 image references found in this browser are migrated to IndexedDB to prevent localStorage from filling up. IndexedDB-only preview images are not public across devices; upload them again to Supabase Storage if the dashboard indicates they are local-only.

E. HOMEPAGE YOUTUBE VIDEO
The Home YouTube video panel accepts a YouTube watch/share URL and displays a small preview/player on the homepage. It cannot upload a video file directly to YouTube. Upload the video to your YouTube account first, then paste the resulting YouTube URL in the admin panel.

F. NEWS, CATEGORIES AND PUBLISHING
- The Article desk loads news from Supabase when the connection and RLS policies are valid. Each live story has Edit, Publish/Unpublish and Delete controls. Local unsynced drafts remain in the browser until they are saved to the database.
- The category manager allows category-specific images. Category images, slider settings, the homepage video and admin-managed settings are stored in site_settings so public pages can read the permitted display values.
- The homepage slider supports up to 16 images.
- Admin UI theme (white/dark) is saved for the current browser.

G. SECURITY AND TESTING
1. Keep Row Level Security enabled. The provided schema grants public SELECT only where needed for published posts, categories, approved comments, public display settings and public media. Admin writes require an authenticated admin profile.
2. Test sign-in and sign-out, owner-only invitations/deletions, image upload from a phone, image display on a second browser/device, publishing/unpublishing, category covers, the homepage slider and YouTube frame before announcing the site.
3. If the website shows “saved in this browser only”, the change was not shared to other visitors. Check the Supabase URL/public key, database policies, Storage bucket and authenticated admin session.

PARROTHIT PATCH NOTES — ADS, NEWS DESTINATIONS, TICKER AND IMAGE LIMIT
---------------------------------------------------------------------
The project uses a maximum uploaded image size of 100 MiB (104,857,600 bytes) in the browser helper and the parrothit-media Storage bucket configuration. Supabase project-level limits and the bucket configuration must both permit this size.

After replacing the project files, run the updated supabase/schema.sql in the Supabase SQL Editor so public pages can read the display-only settings keys moving_text, news_cards, and advertisement_cards. Writes remain restricted to authenticated PARROTHIT administrators by the site_settings policies. If the SQL editor reports a policy already exists, the script drops/recreates the named public display policy.

The 16 feature news-card controls now include a required destination URL and publish records through the news_cards site_settings key. Page-specific ad controls publish to advertisement_cards. Ticker controls save to moving_text. If the dashboard reports a local-only save or shared publishing failure, verify the administrator is signed in and that the updated schema/policies have been applied.

Uploaded image files are limited to 100 MiB. Image URLs pasted into URL fields are remote assets and are not subject to a local-file size check. For performance and mobile data use, compress images where possible even though the upload ceiling is 100 MiB.


Suspended administrator appeals
The `admin_appeals` table stores suspension appeals (maximum 250 words). Only the active Owner can read or review them. Re-run `supabase/schema.sql` after this update to install the table and RLS policies.

PARROTS INTERACTION MEMBER LOGIN UPDATE (OCTOBER 2026)
1. Open the Supabase project connected in supabase-config.js.
2. Open SQL Editor -> New query.
3. Paste and run the complete contents of supabase/community-interaction.sql.
4. In Authentication -> Providers, make sure Email is enabled. If email confirmation is enabled, new users must click the confirmation email before they can log in.
5. Deploy the updated website files. Do not publish any Supabase secret/service-role key in browser files.
6. On Parrots Interaction, the post composer, comment boxes, emoji picker, voice recorder and image-upload icon are visible while signed out. Registration/login is required before posting, commenting, reacting, replying, reporting, or recording voice.
7. A signed-in user can use Log out at any time and log in again later. Supabase records the community member's user ID, email, display name, created time and last-seen time in public.community_members. RLS limits member profile access to the signed-in member.

Important current limitation: this update records community accounts in Supabase, but the existing community post feed still saves posts/comments/reactions in the current browser's local preview storage. They are not yet shared between different visitors/devices. A fully shared community feed needs a separate database/storage integration and policies; do not treat browser-local posts as a shared live feed.
